## Project Overview

SmartTraffic AI is a real-time vehicle monitoring and license plate recognition system. It runs an async AI loop on the backend that continuously processes video frames, detects vehicles and license plates via YOLOv5, reads plate text with EasyOCR, persists unique detections to PostgreSQL, and broadcasts results to connected frontend clients over WebSocket.

## Development Setup

### Running the full stack

```bash
docker compose watch        # hot-reload development
docker compose up --build   # regular start
docker compose logs backend # service-specific logs
```

### Running backend locally (without Docker)

```bash
cd backend
uv sync              # install dependencies into .venv (first time)
uv run fastapi dev app/main.py
```

### Running frontend locally (without Docker)

```bash
# from project root
bun run dev
```

When mixing local and Docker services, stop the Docker service for the one you want to run locally (e.g. `docker compose stop backend`) — ports are shared by design.

## Frontend Commands

Run from `frontend/` or project root (package.json scripts are proxied):

```bash

bun run build         # tsc + vite build
bun run test          # playwright e2e tests
bun run test:ui       # playwright with interactive UI
```

### Regenerating the API client

After backend route changes, regenerate the typed frontend client:

```bash
bash scripts/generate-client.sh
```

The client is generated by `@hey-api/openapi-ts` from `frontend/openapi.json` into `frontend/src/client/`. Do not edit `src/client/` manually — it is fully auto-generated.

## Pre-commit / Linting

[prek](https://prek.j178.dev/) (a modern pre-commit alternative) is configured in `.pre-commit-config.yaml`. Install it once from `backend/`:

```bash
uv run prek install -f
```

```bash
uv run prek run --all-files
```

## Architecture

### AI Detection Pipeline

The core loop runs at backend startup as an `asyncio` task (`detection_engine.py:real_ai_detection_loop`):

```
video.mp4 (looped) → OpenCV frame → resize 960×540 → every 3rd frame:
  → vehicle_detector.py  (YOLOv5, weights/vehicle_best.pt)
  → plate_detector.py    (YOLOv5, weights/plate_best.pt)
  → ocr_reader.py        (EasyOCR on cropped plate region)
  → vehicle_matcher.py   (spatial match plate bbox → vehicle type)
  → save unique plates to PostgreSQL + storage/detections/
  → broadcast JSON to all WebSocket clients via ConnectionManager
```

The `saved_plates` set in `detection_engine.py` is an in-memory dedup guard — it resets on restart.

### Backend Structure

- `app/main.py` — FastAPI app entry: mounts `/storage` static files, fires startup task, sets CORS
- `app/core/config.py` — All settings via `pydantic-settings` from `../.env` (one level above `backend/`)
- `app/api/deps.py` — Shared FastAPI dependencies: `SessionDep`, `CurrentUser`, `CurrentSuperUser`
- `app/api/routes/` — Route modules: `login`, `users`, `detection`, `analytics`, `ws`, `utils`, `private`
- `app/api/routes/ws.py` — Single WebSocket endpoint at `/ws/detections`; delegates to `ConnectionManager`
- `app/services/websocket_service.py` — `ConnectionManager` singleton (`manager`) with broadcast + disconnect cleanup
- `app/models/` — SQLModel table definitions: `User`, `Detection`, `Camera` (all use UUID PKs)
- `app/schemas/` — Pydantic request/response schemas separate from DB models
- `app/ai/` — Four AI modules loaded at import time (YOLO models are singletons)

### Frontend Structure

- Uses **TanStack Router** with file-based routing under `src/routes/`. Routes under `_layout/` require auth.
- **TanStack Query** manages all server state; `src/client/` is the generated typed API client.
- Auth: JWT token stored in `localStorage`, injected into every request via `OpenAPI.TOKEN` in `main.tsx`. On 401/403, the token is cleared and the user is redirected to `/login`.
- `src/components/` is organized by feature (`Dashboard/`, `Detection/`, `History/`, `Analytics/`, `Camera/`, `Admin/`) plus shared `Common/` and `ui/` (shadcn components).

### Database

PostgreSQL accessed via SQLModel + psycopg3. Alembic migrations live in `backend/app/alembic/versions/`. The backend also calls `SQLModel.metadata.create_all(engine)` on startup as a safety net.

Key relationships: `Camera` → `Detection` (one-to-many, cascade delete configured in migration `1a31ce608336`).

### Environment Variables

The `.env` file lives at the project root (not inside `backend/`). Required variables:

```
POSTGRES_SERVER, POSTGRES_USER, POSTGRES_PASSWORD, POSTGRES_DB
SECRET_KEY, PROJECT_NAME
FIRST_SUPERUSER, FIRST_SUPERUSER_PASSWORD
```

`ENVIRONMENT` must be `local`, `staging`, or `production`. The `private` API router is only mounted in `local`.
